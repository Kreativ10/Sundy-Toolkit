# Проверки и ограничения

Проверено 10 октября 2026 года. Проверки выполнялись локально и в одноразовом контейнере; это не проверка пользовательского production-сервера.

## Найденные причины сбоев Minecraft

| Проблема | Исправление |
| :--- | :--- |
| Проверялось только наличие `java`, без версии; установка всегда выбирала Java 21 | Требование Vanilla берётся из манифеста Mojang; выбранная Java проверяется и сохраняется абсолютным путём |
| Относительный путь к новому JAR повторно дополнялся каталогом сервера | Нормализация каталога и JAR выполняется до создания/регистрации |
| Bundler мог запускаться на старой Java, хотя вложенный сервер требовал более новую | При регистрации проверяются также метаданные вложенного серверного JAR |
| Непроверенные имя, память и неоднозначный JAR | Валидация до изменений; неоднозначный JAR нужно выбрать явно |
| OpenRC пытался запускать foreground-процесс без background/supervisor | Фоновая служба с PID-файлом или `supervise-daemon` при включённом перезапуске |
| SIGTERM не обрабатывался supervisor; штатная остановка мира не координировалась | Обработка SIGTERM/SIGINT, команда `stop`, ожидание завершения и ограниченный принудительный останов |
| Медленная консоль блокировала чтение вывода Java | Ограниченные очереди на клиента, отключение зависших клиентов |
| Scanner ограничивал длину строки; Wait мог закрыть stdout/stderr до чтения | Вывод передаётся через `io.Writer`, управляемый `os/exec`; сохраняется финальный вывод |
| Второй supervisor удалял сокет уже работающего экземпляра | Межпроцессная блокировка до изменения сокета |
| Ошибки вложенных операций терялись в dashboard | Общий обработчик ошибок в интерактивном меню |
| Новый buffered reader на каждый вопрос терял уже прочитанные ответы | Общий reader, обработка EOF без автоматического согласия |
| Рамки считали байты/ANSI-коды, а не видимые колонки | Unicode display width, отдельный padding, ограничение шириной терминала |

Первоначальные тесты проходили, но почти не покрывали supervisor, службы, ввод и создание серверов. Новые регрессионные тесты воспроизводят эти сценарии.

## Воспроизведение

```sh
make check
make smoke
make dist VERSION=0.1.0

GOTOOLCHAIN=go1.23.12 go test ./...

SUNDY_MC_E2E_VERSION=latest go test -race -tags=integration \
  -run TestRealVanillaLifecycle -v ./internal/minecraft -timeout 8m

make build
docker build -f scripts/integration/Dockerfile.openrc -t sundy-openrc-test .
docker run --rm --memory=4g --cpus=4 sundy-openrc-test

docker run --rm -v "$PWD:/mnt:ro" koalaman/shellcheck:v0.11.0 \
  installer/install.sh installer/uninstall.sh scripts/smoke.sh \
  scripts/test-installer.sh scripts/integration/openrc.sh
```

Интеграционные тесты Minecraft принимают EULA только для временных тестовых серверов. Контейнер OpenRC использует сеть Docker; отдельная fixture-служба удовлетворяет зависимость `net`. Предупреждения OpenRC о недоступном cgroup в таком контейнере не означают проверку управления cgroup на полноценном хосте.

## Что требует отдельного окружения

- Реальная сетевая реконфигурация, проверка отката после потери связи и применение firewall не выполнялись на рабочем хосте.
- Автоматический откат конфигурации остаётся попыткой восстановления файлов; это не транзакционный снимок диска и не резервная копия миров/БД.
- Полный install/upgrade Pterodactyl, Wings с подключением к Panel, TLS и публичный доступ требуют отдельного стенда.
- Forge/Fabric/Paper/Purpur и произвольные модпаки не проходили реальный runtime-тест. Поддерживается запуск JAR; сборки с обязательным shell-скриптом/argfile нужно запускать их штатными средствами.
- Причины сбоев найдены в коде и воспроизведены тестами. Логи исходного пользовательского хоста в репозитории отсутствуют, поэтому его конкретный аварийный запуск не подтверждён этими проверками.

Документация Go `os/exec` и `os/signal`, а также ширина Unicode в go-runewidth проверялись через Context7. OpenRC, Minecraft, Composer и параметры Panel сверялись с первичными источниками, указанными в README.
